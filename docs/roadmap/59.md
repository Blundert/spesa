# Task 59 — Data layer catalogo piatti (dishes + dishIngredients)

## Contesto

Prima task della feature "catalogo piatti riutilizzabile" concordata con l'utente
(sessione di grilling): un piatto salvato una volta, con ingredienti che referenziano
il catalogo `Item` esistente, riusabile tra settimane diverse di pianificazione pasti.
Questa task copre solo lo strato dati — nessuna UI.

## Decisioni chiave (dalla sessione di grilling)

- Ingredienti di un piatto = riferimenti a `Item` esistenti (stesso catalogo/dedup
  usato da `ListaScreen`), non un'entità testuale indipendente.
- Nessuna quantità per ingrediente: un piatto è una checklist di `Item`; la somma
  delle occorrenze avviene più avanti, all'import in lista (task futura), riusando
  `addToList` che già incrementa se l'item è presente.
- Le pianificazioni pasti già esistenti (`MealPlan.dish` come stringa libera)
  **non vengono migrate**: restano di sola lettura col vecchio formato. Il nuovo
  collegamento (`dishId`) sarà aggiunto solo per le pianificazioni create da qui
  in avanti (task futura).

## Schema

- `src/db/types.ts`: nuovi tipi `Dish { id?, name, normalizedName }` e
  `DishIngredient { id?, dishId, itemId }`.
- `src/db/db.ts`: **v8** Dexie — nuove tabelle `dishes: '++id, normalizedName'` e
  `dishIngredients: '++id, dishId, itemId, [dishId+itemId]'`. Nessun upgrade dati
  (tabelle nuove, vuote). Aggiunte anche a `wipeAllData()`.

## Repository

`src/db/repositories/dishes.ts`:
- `getDishes`, `getDishById`, `findDishByName` (dedup lookup)
- `upsertDish(name)` — crea solo se non esiste già un piatto con lo stesso
  `normalizedName` (stesso pattern di `upsertItem`), usato dalla creazione "al volo"
- `renameDish`, `deleteDish` (elimina anche i suoi `dishIngredients`, in transazione)
- `getDishIngredients(dishId)` → `Item[]` (join, scarta item eliminati)
- `setDishIngredients(dishId, itemIds)` — sostituisce l'intero elenco (delete + bulkAdd)
- `getDishesWithIngredients()` — tutti i piatti con ingredienti (riduzione in JS,
  stesso pattern di `getPlannedWeeks`/`getListItems`: volumi piccoli, app personale)

## Backup

Il catalogo piatti è dato utente: va incluso nell'export/import.
- `BACKUP_VERSION`: 6 → 7.
- `BackupData.dishes?` / `BackupData.dishIngredients?` (opzionali — assenti nei
  backup precedenti alla v7).
- `exportData()` li include sempre; `importData()` usa `?? []` per i backup
  vecchi che non li hanno (stesso trattamento di `settings` per la v4).

## Nota su versionamento

Nessun bump di versione applicativa (patch/minor) e nessuna entry in
`src/data/changelog.ts`: questa task non introduce alcun comportamento visibile
all'utente (solo schema DB + repository, nessuna schermata). Per coerenza con la
convenzione del progetto ("fix → patch", "feature → minor"), il bump avverrà alla
prima task che rende la feature effettivamente usabile (schermata Catalogo piatti).
