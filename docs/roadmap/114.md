# Task 114 — Fix: conflitto subito dopo aver condiviso (1.1.4)

Segnalazione: "Un altro stava modificando la lista: riprova tra poco" creando una lista condivisa, senza aver invitato nessuno.

## Causa (probabile, non riprodotta su GitHub vero)
Dopo "Condividi" la lista risulta condivisa e la schermata avvia da sola la sync (`useLiveSharedList`) mentre `shareList` ne sta già facendo una:
due scritture quasi insieme sullo stesso file, che GitHub rifiuta (409/422); i 3 tentativi erano immediati, quindi fallivano uguale. Non c'entra nessun altro utente.
In più, al fallimento `shareList` scollegava la lista ma lasciava il repo creato: riprovando col nome uguale usciva "esiste già".

## Fatto
- `syncSharedList` è **una sola per lista alla volta**: una richiesta mentre un'altra gira riceve lo stesso risultato.
- **Pausa crescente** (400 ms × tentativo) tra un tentativo e l'altro dopo un conflitto.
- `shareList`: con conflitto o niente rete alla prima scrittura la lista **resta condivisa** (`pending`) e la sync che si ripete finisce il lavoro;
  con altri errori si torna indietro come prima. Se il nome è già usato da un repo **mio, scrivibile e senza lista dentro** lo riusa.
- Messaggio del conflitto più chiaro; toast "Lista condivisa: finisce di sincronizzarsi tra poco".
- Test al 100%; versione 1.1.4, changelog, badge, `test/smoke.md` (Flusso 54).

## Da sapere
- Non provato contro GitHub vero: se il problema persistesse, la causa sarebbe un'altra (es. comportamento del repo vuoto con `branch` nel `PUT`) e il messaggio
  d'errore ora è più utile per capirlo. Dimmi cosa vedi.
