# Task 123 — F2: le letture da GitHub non usano più la cache del browser (1.4.2)

Richiesta: correggere i problemi trovati dal run e2e (`docs/roadmap/122.md`). Questo è il primo: F2.

## Causa
`getRemoteFile` e gli altri `fetch` di lettura non indicavano `cache`: GitHub risponde ai GET con `Cache-Control: private, max-age=60`, quindi il browser restituiva per 60 s contenuto e `sha` vecchi. Effetti misurati: una modifica dell'altro arrivava dopo 33 s invece di ≤20 s e i `PUT` successivi andavano in `409` a ogni ciclo.

## Fatto
- `NO_CACHE = 'no-store'` in `src/lib/gitSync.ts`, usato in tutte le letture: `getRemoteFile` (e il `download_url`), `githubJson`, `listRemoteHistory`, `fetchRepoMeta`, `listInvitations`, `fetchViewer`, `listAccessibleRepos`, `repoCanPush`.
- Test: `src/lib/noCache.test.ts` (ogni lettura chiede il dato fresco) e un caso in `sharedSync.test.ts` (controllo del permesso + lettura del file).
- Versione 1.4.2, changelog, badge README, smoke (Flusso 49.10).

## Verifica
Test, coverage 100%, tsc, eslint e build puliti. La verifica nel browser con la cache attiva (senza CDP) è nel run di verifica a fine lavoro.
