# Task 60 — Schermata Catalogo piatti (v0.24.0)

## Obiettivo

Rendere usabile il catalogo piatti introdotto nella task 59: una schermata dedicata
per creare, modificare ed eliminare piatti, con i loro ingredienti scelti dal
catalogo `Item` esistente (stesso autocomplete di `ListaScreen`).

## File nuovi

- `src/screens/PiattiScreen.tsx` — elenco piatti (card bianche stile Catalogo,
  nome + conteggio ingredienti, edit/delete) + bottom sheet unico per
  creazione/modifica (nome + chip ingredienti rimovibili + input con
  autocomplete, stesso pattern pool BASE_ITEMS+db.items di `ListaScreen`) +
  bottom sheet di conferma eliminazione.
- `src/hooks/useDishes.ts` — `useDishes`, `useSaveDish`, `useDeleteDish`.

## File modificati

- `src/db/repositories/dishes.ts` — nuova `saveDish(id, name, itemIds)`: crea/
  aggiorna nome + sostituisce ingredienti in un'unica chiamata (usata sia dalla
  creazione che dalla modifica nella UI).
- `src/db/repositories/dishes.test.ts` — test per `saveDish`.
- `src/hooks/useItems.ts` — nuovo `useUpsertItem()` (crea/riusa un `Item` senza
  aggiungerlo alla lista della spesa — serve al picker ingredienti, diverso da
  `useAddNewItemToList` che invece aggiunge anche alla lista).
- `src/db/queryKeys.ts` — `qk.dishes()`.
- `src/router.ts` — route `/piatti` sotto `shellRoute`.
- `src/components/AppShell.tsx` — voce "Piatti" nel `MenuSheet`, tra Catalogo e
  Statistiche.
- `src/i18n/locales/it.ts` + `en.ts` — namespace `piatti`, `nav.dishes`; aggiornato
  `settings.confirmBody` per menzionare anche i piatti salvati (ora azzerati da
  `wipeAllData`, vedi task 59).
- `src/data/changelog.ts` + `package.json`/`package-lock.json` — versione 0.24.0.
- `test/smoke.md` — nuovo Flusso 12.

## Decisioni di dettaglio (non specificate esplicitamente, scelte più semplici)

- Il picker ingredienti crea sempre l'`Item` via `upsertItem` anche quando si
  clicca un suggerimento già esistente (stesso comportamento di `ListaScreen`,
  che fa lo stesso per coerenza — l'operazione è idempotente per nome
  normalizzato).
- Lo stato dell'editor (`EditorState.ingredients`) tiene `{id, name}` invece dei
  soli `itemId`, per evitare un flash di "nome mancante" nella chip mentre la
  query `items` si re-invalida dopo la creazione di un nuovo `Item`.
- Nessun link diretto dalla schermata Pasti al catalogo piatti in questa task
  (fuori scope — riguarda la task 3, integrazione pianificazione).
