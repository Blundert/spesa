# Task 121 — Piano e2e di sincronizzazione tra due account GitHub

Richiesta: tre repo di test (backup A, backup B, lista condivisa) e account dedicati per provare davvero la condivisione delle liste, in una sezione/file a parte, con focus sui problemi di sincronizzazione. Decisioni prese con un'intervista (grilling).

## Decisioni
- **Due** account GitHub di test dedicati (A e B), **un** token classico ciascuno (`repo` + `delete_repo`): l'app ha un solo token per dispositivo, non uno per repo.
- Repo di backup creati a mano; `spesa-condivisa` lo crea l'app (Flusso 47) e lo cancello con `gh api` prima di ogni run.
- Token in `.env.e2e` (in `.gitignore`), mai in log o screenshot.
- Build di produzione su `vite preview`: A su `localhost:4173`, B su `127.0.0.1:4173` (IndexedDB separato per origine).
- File separato `test/e2e-sync.md` (non `smoke.md`), solo su richiesta; ogni scenario su mobile 390 e desktop 1280.
- Otto scenari: concorrenza, eliminazione vs modifica, offline, spese in contemporanea, ripristino da backup, budget/uncounted, accesso perso, ciclo di vita del telefono.
- Tecniche: `page.route` per offline/rete lenta per scheda, `visibilitychange` per lo sfondo, `page.close()` + riapertura per la chiusura vera, tempi reali (5 s push, 15 s polling).
- I problemi trovati si **registrano, non si correggono**: ogni fix è una task a parte, decisa dall'utente.

## Fatto
- `test/e2e-sync.md` (preparazione, reset, tecniche, scenari 0–8, registro dei problemi), `.gitignore` con `.env.e2e`.
- Nessun codice toccato: niente bump di versione né changelog.

## Da guardare nell'esecuzione (dal codice di `sharedSyncScheduler.ts`)
- Il push da 5 s è un `setTimeout` in memoria: chiudendo l'app entro i 5 s la modifica resta nel DB locale ma parte solo alla prima sync riuscita; `setVisible(false)` non fa il flush.
- Il polling e la sync partono con `start(listId)`, cioè all'apertura della lista: da verificare se una modifica in sospeso parte dopo un riavvio senza aprirla.

## Non fatto / prossimo
- Esecuzione degli e2e: task successiva, quando l'utente fornisce i due token.
