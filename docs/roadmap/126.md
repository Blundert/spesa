# Task 126 — F7: le spese non si duplicano dopo il ricollegamento (1.4.5)

## Causa
`importSharedSessions` considerava "già presenti" solo le spese della STESSA lista locale (`where('listId')`). Dopo "Tieni come lista normale" e un nuovo "Aggiungi una lista condivisa" la lista locale è un'altra (id diverso): le spese con lo stesso `sharedUid` venivano reimportate. Nel run e2e B si ritrovò con 4 sessioni invece di 2 e "Totale speso € 1,80" invece di 0,90.

## Fatto
- `sharedSessionsData.ts`: `known` si calcola su tutte le spese del dispositivo (l'identificatore è unico). Nessun indice su `sharedUid`: scansione in memoria (poche spese).
- Test in `sharedSessionsData.test.ts` (fallisce senza il fix). Versione 1.4.5, changelog, badge README, smoke (Flusso 50, 5bis).

## Non cambiato (segnalato)
Il ricollegamento crea una seconda lista con lo stesso nome della lista tenuta come normale: è coerente (sono due liste diverse) ma può confondere; si archivia quella vecchia.

Test, coverage 100%, tsc, eslint, build. Nel browser a fine lavoro: ripetizione del caso del run e2e.
