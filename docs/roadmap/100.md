# Task 100 — Branch (v0.48.0)

Sesta task del piano.

## Fatto
- `gitSync.ts`: `listBranches`, `createBranch` (dal commit attuale del branch attivo, 422 → "Esiste già"),
  `switchBranch` (legge il file dell'altro branch, salva una copia locale e committa il backup del locale non
  sincronizzato sul branch che si lascia, bloccante; poi import, `branch` nella configurazione e stato di sync
  riallineato), `loadRemoteBackup(branch?)`. Nome del branch validato da `isValidBranchName` (regole di git, prudenti).
- Sezione "Branch" nella pagina Sincronizzazione, mobile e desktop (`SyncBranches`, componente condiviso con
  conferme in riga): elenco, "Passa a", "Unisci qui", crea da qui. Dopo un passaggio il modulo rilegge la
  configurazione (`useGitSyncSettings.refresh`).
- "Unisci qui" apre `/sincronizzazione/unisci?from=<branch>`: stessa schermata di unione, con il branch scelto
  come "remoto"; l'applicazione scrive UN commit "Merge …" sul branch attivo (dati + backup di locale e remoto).
  `useMerge(onDone, from)`; `validateSearch` nei due router.
- Guida: voce "Branch". Test al 100% (`FakeGithub` ora conosce i branch).

## Verifica
Nel browser con GitHub simulato a 390 e 1280 px: nome non valido, creazione, conferma e passaggio (i dati diventano
quelli del branch, il campo Branch del modulo si aggiorna). Non provato contro GitHub vero.

## Scelte / da sapere
- Nessuna eliminazione di branch (operazione distruttiva e fuori dal piano): si fa su GitHub.
- Il backup del locale prima di un passaggio finisce sul branch che si lascia, non su quello di arrivo.
- Il merge tra branch usa come "locale" i dati di adesso, che si assumono allineati al branch attivo.
- Il nome del branch ammesso in creazione è volutamente più stretto di quello di git.
