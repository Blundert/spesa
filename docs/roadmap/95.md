# Task 95 — Sync: backup della scelta scartata (v0.44.0)

Prima task del piano "rete di sicurezza + cronologia + merge" (conflitti di sync che facevano perdere dati).

## Fatto
- `gitSync.ts`: `commitFiles` = UN commit con più file (Git Data API: ref → commit → albero → commit → PATCH ref
  senza `force`; se il branch è avanzato, 422 → "Il remoto è cambiato durante il salvataggio: riprova").
- "Mantieni" (`syncPushForce`): un commit con `spesa-db.json` nuovo + `backups/<ISO>-remote.json` (remoto scartato).
- "Usa remoto" e "Scarica da remoto" (`syncPull`): prima il commit di `backups/<ISO>-local.json` (bloccante: se
  fallisce, nessun import), poi l'import. Il commit si salta se il locale è solo dati iniziali o è identico
  all'ultimo sync (è già nella cronologia del repo).
- Copia di sicurezza in IndexedDB (Dexie v10, tabella `safetySnapshots`, ultime 10) prima di "Usa remoto"/pull e
  prima dell'import da file. Non fa parte del backup (`exportData` non la include).
- Locale con soli dati iniziali (`isInitialData`) + remoto presente + conflitto → pull diretto, niente toast.
- Toast con il percorso del backup salvato (`settings.syncBackupSaved`), condiviso da mobile e desktop
  (`toastWithBackup`).
- Test al 100%: `gitSync.ts` e `syncRunner.ts` entrano in `coverage.include`; `fakeGithub.ts` è una finta API
  (Contents + Git Data) usata solo dai test.

  `localStorage` bastano, e il codice di produzione resta com'è.

- Le copie in IndexedDB non hanno ancora una schermata per ripristinarle: arrivano con la Cronologia (task 4 del piano).
