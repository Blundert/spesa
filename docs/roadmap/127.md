# Task 127 — F5: "Solo guarda" non si può dare sui repo personali (1.4.6)

## Causa
L'app crea i repo con `POST /user/repos`, cioè sempre nell'account di chi condivide. GitHub non ammette collaboratori in sola lettura sui repo di account personali (`422 Cannot assign … permission of read`; la sola lettura esiste solo nelle organizzazioni). Il selettore "Solo guarda" non poteva mai funzionare e `inviteToList` traduceva ogni 422 in `user-not-found`, dando "Utente GitHub non trovato" per un utente che esiste.

## Decisione (la più semplice, da segnalare)
Tolto il selettore dai due punti di invito di `ShareSection` (componente unico per mobile e desktop): si invita sempre con `push`. La parte che riceve un invito in sola lettura (`canWrite:false`, banner, niente scritture) resta, perché può arrivare da un repo di un'organizzazione; la libreria continua ad accettare `pull`.
Alternativa scartata: lasciare l'opzione disabilitata con un avviso (UI morta). Se in futuro si vorranno i repo nelle organizzazioni, si riaggiunge il selettore solo quando il proprietario è un'organizzazione.

## Fatto
- `ShareSection.tsx`: niente `PermissionSelect`, `INVITE_PERMISSION = 'push'`; tolte le chiavi `shared.permWrite/permRead` da it/en.
- `sharedLists.ts`: 422 nell'invito → nuovo codice `cannot-invite` ("GitHub non accetta questo invito…"); 404 resta `user-not-found`. `sharedErrors.ts`, it/en e test aggiornati.
- Smoke (Flusso 47). Versione 1.4.6, changelog, badge README.

## Non risolto
La sola lettura reale non è testabile con account personali: serve un repo di organizzazione (resta in `test/e2e-sync-da-testare.md`).
