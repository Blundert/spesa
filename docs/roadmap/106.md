# Task 106 — Merge automatico e sync di una lista condivisa (nessuna versione)

Task 3 del piano "liste condivise". Nessuna interfaccia: logica pura, livello dati e motore di sync. Nessun bump.

## Fatto
- **Formato del file** (`src/lib/sharedListFile.ts`, puro, 100%): `spesa-shared-list` v1 con `uid`, `name`,
  `nameUpdatedAt`, `items` (uid, nome, categoria per nome, quantità, autore, date, `takenBy`), `tombstones` e
  `sessions` (spese concluse, già nel formato per non doverlo cambiare nella task 6).
- **Validazione rigida** (`parseSharedFile`, il file lo scrivono anche altri): max 1 MB, 2000 voci, 500 spese, nomi max
  120 caratteri, quantità 1–9999, importi interi, date entro il 2100, login GitHub e uid solo nei caratteri ammessi
  (così niente `__proto__`), niente caratteri di controllo, uid mai ripetuti. File di una versione più nuova → errore a parte.
- **Merge** (`mergeSharedFiles`, simmetrico e senza domande): voci per uid, vince la modifica più recente (a parità, sempre la
  stessa); l'eliminazione vince su una voce non più recente, una modifica successiva la fa tornare; voci con lo stesso nome
  (aggiunte in parallelo) diventano una con le quantità sommate; spese unite per uid; tombstone dimenticati dopo 30 giorni.
- **Dati** (`sharedListData.ts`): `exportSharedFile` (assegna gli uid, ripulisce nomi e quantità perché il nostro file
  passi sempre la validazione), `applySharedFile` (crea/aggiorna/toglie le voci, collega gli articoli al catalogo per
  nome e li crea nella categoria omonima o in "Altro", aggiorna nome e tombstone), `patchSharedLink`.
- **Scritture sulle voci** (`listItems.ts`, `items.ts`): nelle liste condivise aggiungere dà uid/autore/data, cambiare la
  quantità aggiorna la data, ogni eliminazione (voce, quantità 0, fine spesa, svuota lista, articolo tolto dal catalogo)
  lascia un tombstone (`tombstoneListItems`). Per le liste normali non cambia niente. Rinominare una lista condivisa segna
  `shared.nameUpdatedAt`.
- **Sync** (`sharedSync.ts`, `syncSharedList`): scarica, unisce, scrive solo se c'è qualcosa di nuovo, applica il risultato.
  - **Prima sync** (collegamento senza `lastSha`: lista appena aggiunta o dopo un ripristino da backup): unisce ma NON
    scrive; scrive la sync dopo. Se il repo è vuoto crea il file.
  - **Sola lettura**: la copia locale diventa quella del repo; il permesso si rilegge alla prima sync e si aggiorna se
    GitHub risponde 403 in scrittura.
  - **Conflitti di scrittura** (409/422): fino a 3 tentativi, poi `conflict`.
  - Errori tipizzati (`SharedSyncError`): `no-token`, `auth`, `no-access`, `invalid-remote`, `newer-format`, `read-only`,
    `conflict`, `network`.
- `getRemoteFile` e `putFile` di `gitSync` ora sono esportati.
- Test al 100% (file, dati, repository, sync con `FakeGithub`).

## Da sapere
- **"Niente HTML" nel file**: non rifiuto `<` e `>` (un articolo "Pane <3" non deve bloccare la sync). I testi si mostrano
  sempre come testo di React (mai come HTML) e la CSP non ammette script inline: un nome con HTML non può eseguire niente.
- Rinominare un articolo nel catalogo locale non propaga la modifica alla lista condivisa (non cambia `updatedAt` della
  voce); aggiungere la voce con un altro nome sì.
- Le spese concluse non sono ancora collegate: `exportSharedFile` esporta `sessions: []`, ma il merge conserva quelle che
  trova nel repo, quindi nessuna spesa si perde. Arrivano con la task 6.
- `takenBy` ("preso da Anna") viaggia già nel file e nel merge; chi lo imposta e lo mostra è la task 5.
- Un dispositivo fermo per più di 30 giorni può far ricomparire voci eliminate nel frattempo (tombstone già dimenticati).
- Se il catalogo locale non ha nemmeno una categoria `applySharedFile` fallisce; nell'app le categorie di serie ci sono sempre.
- `test/smoke.md` non cambia: niente di visibile all'utente in questa task.
