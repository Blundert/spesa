# Task 104 — Modello dati e collegamento delle liste condivise (nessuna versione)

Task 1 del piano "liste condivise". Nessuna interfaccia: solo dati, funzioni pure e repository. Nessun bump (la
versione è 1.0.0, la 1.1.0 arriva con l'ultima task).

## Fatto
- `ShoppingList.shared?: SharedLink` (`src/db/types.ts`): `uid` stabile, `owner/repo/branch/path` del repo dedicato,
  `me` (login GitHub di questo dispositivo), `canWrite`, `members` (login → nome visibile + tipo `partner`/`stranger`),
  `tombstones` (uid voce → quando è stata eliminata) e `lastSha`. **Mai il token.** Nessun cambio dello schema Dexie:
  sono campi opzionali non indicizzati.
- `ListItem`: `uid`, `updatedAt`, `addedBy`, `takenBy` opzionali, usati solo nelle liste condivise (gli id numerici
  sono diversi su ogni dispositivo, serve un identificatore stabile; vince la modifica più recente).
- `src/lib/sharedList.ts` (puro, 100%): `newUid()`, `parseRepoRef()` (legge `owner/repo`, indirizzi GitHub e
  `git@github.com:…`), `SHARED_LIST_PATH = 'lista.json'`.
- Repository: `getSharedLists()`, `setSharedLink(id, link | null)` (null = scollega, lista normale),
  `assignListItemUids(listId, me)` (idempotente).
- **Backup**: porta il collegamento ma toglie `lastSha`, sia in export sia in import. Senza `lastSha` la lista non sa
  cosa c'è nel repo: la prima sync scarica e non sovrascrive mai il lavoro degli altri (task 3 lo deve rispettare).
  Il `lastSha` toglie anche una causa di cambi inutili dell'impronta del backup personale a ogni sync.
- Test al 100% (`sharedList`, repository liste e voci, backup).

## Da sapere
- **Le eliminazioni non scrivono ancora il tombstone**: `removeFromList`, `clearList` e `removePurchasedFromList`
  cancellano la riga e basta. Il collegamento con `shared.tombstones` si fa nella task 3 insieme al merge, perché lì
  si decide anche quando potarli.
- Le sessioni (spese concluse) non hanno ancora i campi per l'autore: arrivano con la task 6.
- Se un backup personale viene scaricato (`syncPull`) sostituisce anche le liste condivise locali: il repo
  condiviso resta la fonte di verità e la prossima sync le riallinea. Eventuali modifiche non ancora inviate si perdono.
- `test/smoke.md` non cambia: niente di visibile all'utente in questa task.
