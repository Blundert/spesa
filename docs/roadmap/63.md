# Task 63 — Autocomplete in "Aggiungi fuori lista" (v0.27.0)

## Obiettivo

Durante la spesa reale, il bottom sheet "Aggiungi fuori lista" (`SpesaScreen`)
era solo testo libero, senza alcun aiuto a riconoscere un articolo già nel
catalogo — a differenza di `ListaScreen`, che ha già un dropdown di
suggerimenti. Risultato: facile creare doppioni quasi identici nel catalogo
`Item`. Portato lo stesso pattern di autocomplete anche qui.

## Decisione (dalla sessione di grilling)

Solo il dropdown di suggerimenti, nessun avviso di conferma aggiuntivo quando
si crea una voce davvero nuova (comportamento già esistente di `upsertItem`,
che dedupe per nome normalizzato).

## Implementazione

- `SpesaScreen.tsx`: nuovo pool di suggerimenti (`BASE_ITEMS` + `items` del
  catalogo, deduplicati per nome normalizzato) — stesso pattern di
  `ListaScreen`/`PiattiScreen`. Il dropdown compare sotto il campo "Nome
  oggetto" mentre si digita, con nome + categoria per ogni suggerimento.
- A differenza di `ListaScreen` (flusso a un passaggio: tap = aggiunto),
  qui il flusso è a due passaggi (nome → prezzo): toccare un suggerimento
  salta direttamente al tastierino prezzi (equivalente a premere anche
  "Continua"), portando con sé il `categoryId` del suggerimento.
- **Risoluzione categoria**: se si conferma testo libero senza toccare un
  suggerimento, `handleConfirmPrice` cerca comunque un match esatto (Item
  esistente o articolo base) per assegnare la categoria corretta invece di
  forzare sempre "Altro" — stesso comportamento di `ListaScreen.handleAdd`.
  Prima di questa task, digitare "Latte" fuori lista lo creava sempre sotto
  "Altro" anche se "Latte" esisteva già in "Frigo" nel catalogo base o
  personale (bug pre-esistente, corretto come effetto collaterale di questa
  task perché necessario per rendere sensato l'autocomplete).
- Questa risoluzione è fatta con fetch fresco (`getCategories`/`getItems`
  dinamici) dentro `handleConfirmPrice`, non leggendo le variabili di
  render (`categories`/`items`/pool) dalla closure — per non aggiungere
  nuove dipendenze al suo `useCallback`. `SpesaScreen.tsx` ha già una
  cascata pre-esistente di errori ESLint `react-hooks/preserve-manual-memoization`
  (12, indipendenti da questa task — il React Compiler non riesce a
  ottimizzare il componente per motivi preesistenti non in scope qui);
  aggiungere dipendenze nuove ai `useCallback` esistenti ne avrebbe aggiunti
  altri 2. Evitato mantenendo la stessa tecnica già usata nel codice
  originale (fetch fresco via import dinamico) invece di leggere dalla
  closure.
